# 현장노트 웹앱

사용자의 요청에 맞춰 기존 현장노트를 유지·개선하거나, 포함된 소스 템플릿으로 별도 앱을 만든다. 템플릿은 완성된 상용 서비스가 아니라 출발점이다. [앱 구조와 현재 제약](references/app.md)을 관련 기능을 수정할 때 읽는다.

## 작업 대상 선택

- **기존 현장노트 수정:** 먼저 사용자가 지정한 체크아웃의 `.openai/hosting.json`과 Git 상태를 확인한다. 경로가 없으면 Sites의 기존 소스 저장소에서 연다. 포함된 스타터를 기존 체크아웃 위에 덮어쓰지 않는다.
- **새 앱 제작:** `python <이 스킬 폴더>/scripts/scaffold.py <새 절대경로>`로 [스타터](assets/starter)를 복사한다. 복사본에는 라이브 사이트 ID·런타임 키·사용자 데이터가 없다. 상호, 예시 문구, 단가, 요금, 도메인, 로그인·결제 설정을 새 서비스에 맞춘다.
- 사용자가 화면 일부만 바꾸길 원하면 기존 기능·데이터·접근 범위를 유지한다. 새 사이트나 공개 전환을 임의로 만들지 않는다.

## 구현 시 지킬 연결

- 화면은 `public/`에, 온라인 API는 `worker.mjs`에, 데이터 구조는 `db/schema.ts`와 `drizzle/`에 있다. 사용자별 문서·파일 소유권 검사를 유지한다. 이미 배포한 마이그레이션은 수정하지 않고 다음 번호를 추가한다.
- 구글 로그인 콜백 `/api/auth/google`은 구글에서 오는 교차 출처 POST다. 이 경로를 일반 API의 동일 출처 검사로 막지 않는다. 대신 Google ID 토큰 서명·대상·발급자·만료와 `g_csrf_token` 쿠키/본문 일치를 확인한다. 기존 계정의 현장·구독을 다른 구글 계정에 연결할 때는 사용자가 지정한 계정을 확인한다.
- 토스 비밀 키와 빌링키 암호화 키는 서버 환경 변수로만 둔다. 템플릿의 9,900원 흐름은 테스트 결제이며, 접속 없이 매월 청구하는 운영 스케줄은 포함되지 않는다. 실거래 자동 청구로 표시하기 전에 상점 계약·라이브 키·예약 실행·실제 결제 검증을 완료한다.
- 사진·음성은 파일 소유권과 크기/형식 검사를 유지한다. 브라우저 받아쓰기는 기기·브라우저 지원에 좌우된다.

## 검증과 배포

관련 변경 뒤 `npm run check`, `npm test`, `npm run build`를 실행한다. 로그인·결제·권한 변경은 허용된 테스트 계정으로 브라우저의 실제 동선까지 확인하고, 확인하지 못한 단계는 완료로 보고하지 않는다. 기존 배포나 새 Sites 배포에는 사용 가능한 `sites:sites` 스킬의 소스 동기화·버전 저장·공개 범위 규칙을 적용한다. 현재 배포의 상태와 설정은 매번 다시 읽는다.
